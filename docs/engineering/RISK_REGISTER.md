# `img-upload-kit` — Risk Register

> Prioritized by real verified evidence from Phase 0 inspection. Updated as risks are mitigated.

| ID | Severity | Affected Module(s) | Evidence | Potential Impact | Proposed Solution | Regression Test Requirement | Status |
| --- | --- | --- | --- | --- | --- | --- | --- |
| **R-01** | **High** | `src/server/security/sanitizeSvg.ts` | Uses regex `FORBIDDEN_ELEMENTS` denylist (`lines 5-25`) rather than an allowlist parser, despite `AGENTS.md` claiming allowlist sanitization. | XSS / script execution / XXE bypass via unlisted tags, namespace tricks, or malformed XML when `allowSvg: true`. | Replace with zero-dep XML tokenizer + strict tag/attribute/URI/CSS allowlist (`svgTokenizer.ts`, `svgAllowlist.ts`) + optional custom `svgSanitizer` hook. | Adversarial SVG suite (`<script>`, `<foreignObject>`, `<use>`, `<math>`, `on*`, CSS escapes, XXE, malformed XML, nested `<svg>`). | Open (Phase 1) |
| **R-02** | **High** | `src/server/handler/presignRoute.ts`, `finalizeRoute.ts`, `uploadToken.ts` | `PresignTokenPayload.sub` is never populated or checked; `finalizeRoute.ts:54` consumes token `jti` *before* `runAuthorize` (`line 73`). | Cross-user token reuse; unauthorized caller can burn a victim's single-use token; no zero-downtime secret rotation. | Add `getSubject` hook, bind `sub` on presign, authorize & verify `sub` *before* consuming `jti`, add `secret: string \| readonly string[]` rotation and `clockToleranceMs`. | Tests for cross-user token, unauthorized burn attempt, concurrent replay race, expired/skewed tokens, rotated secrets. | Open (Phase 1) |
| **R-03** | **Medium** | `src/server/optimization/imageOptimizer.ts` | Lines `208-215` return raw input `buffer` on JPEG passthrough when `orientation <= 1`. | Sensitive EXIF metadata (GPS, camera serial, author) leaks into uploaded images. | Strip metadata on all outputs (re-encode or strip EXIF) unless explicitly configured otherwise. | Test JPEG with embedded EXIF GPS/Make tags verifies metadata is stripped even on passthrough path. | Open (Phase 4) |
| **R-04** | **Medium** | `src/server/optimization/imageOptimizer.ts`, `src/server/security/sniffFormat.ts` | No independent `maxWidth`, `maxHeight`, or `maxFrames` (animated GIF/WebP) guards prior to decoding. | CPU/memory exhaustion (DoS) from high-frame animated images or extreme dimensions. | Add `imageLimits.ts` with configurable `maxWidth`, `maxHeight`, `maxPixels`, `maxFrames` checked via metadata before full decode. | Tests rejecting oversized dimensions, excessive pixel counts, and multi-frame animated payloads. | Open (Phase 1) |
| **R-05** | **Medium** | `src/storage/s3Adapter.ts`, `supabaseAdapter.ts`, `localFsAdapter.ts` | `normalizeS3Key` allows `..`; `supabaseAdapter` lacks path traversal check; `localFsAdapter` lacks symlink `realpath` containment. | Key manipulation / directory escape if caller bypasses handler sanitization. | Reject `..`, `.`, and `\0` segments in S3/Supabase adapters; verify `fs.realpath` containment in `localFsAdapter`. | Traversal & symlink escape tests across all storage adapters. | Open (Phase 1) |
| **R-06** | **Medium** | `src/server/handler/responses.ts`, `src/client/xhrUpload.ts`, `presignedUpload.ts` | Errors return unstructured `{ error: string }`; no rate-limit/quota extension points. | Clients cannot reliably distinguish retryable vs terminal errors; endpoints exposed to abuse without custom middleware. | Introduce `UploadKitError` with `UploadErrorCode` & `retryable`; add `RateLimiter` & `QuotaProvider` handler hooks. | Unit/integration tests for all error codes, redaction of internal causes, and rate-limit `429` responses. | Open (Phase 2) |
| **R-07** | **Medium** | `src/cli/detect.ts`, `src/cli/init.ts` | Blindly installs `sharp` for frontend-only Vite/React and non-Node Edge/Workers projects; no infra/storage detection or safe file generation. | Broken installs in browser-only/edge environments; poor adoption DX. | Implement 4-layer infrastructure detection, runtime/storage capability registries, architecture resolver, safe file/env/`AGENTS.md` managers. | 19-fixture CLI test matrix including Workers, Vite frontend-only, monorepos, and existing `AGENTS.md`/`.env.example`. | Open (Phase 7B) |
| **R-08** | **Low** | `pnpm-lock.yaml` (devDependencies) | `pnpm audit` reports 8 dev-only advisories (`tinypool`, `minimatch`, `esbuild`). Runtime `"dependencies": {}` has 0 advisories. | Local/CI dev toolchain exposure only (zero impact on published npm consumers). | Evaluate targeted devDependency updates in Phase 8/10 while keeping CI green on Node 20/22/24. | Verify `pnpm audit` & full CI pass after upgrades. | Open (Phase 8/10) |
