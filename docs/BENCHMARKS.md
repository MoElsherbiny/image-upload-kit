# Image Optimization Benchmarks

This document reports real, reproducible measurements for `optimizeImage` (`img-upload-kit/server`) generated by [`scripts/benchmark-optimizer.mjs`](../scripts/benchmark-optimizer.mjs).

## 1. How to Reproduce

Build the package and run the benchmark script from the repository root:

```bash
npm run build && node scripts/benchmark-optimizer.mjs
```

The script synthesizes deterministic RGB test images via Sharp (`1200x800` PNG and `1600x1066` JPEG), warms up the Sharp/libvips threadpool, and measures output byte size, savings ratio, wall-clock duration, and process RSS delta across formats, focal cropping, and parallel concurrency.

## 2. Measured Results

**Environment**: Node.js `v22.23.2`, Sharp `0.35.5` (Windows x64).

| Scenario | Out Format | Concurrency | Input | Output | Savings | Duration (ms) | RSS Delta |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| PNG 1200x800 -> Auto (AVIF/WebP) | avif | 1 | 2617.3 KB | 84.2 KB | 96.8% | 548.9 | +5.47 MB |
| PNG 1200x800 -> WebP q80 | webp | 1 | 2617.3 KB | 55.7 KB | 97.9% | 73.9 | +2.80 MB |
| PNG 1200x800 -> AVIF q75 e4 | avif | 1 | 2617.3 KB | 72.4 KB | 97.2% | 252.0 | +3.07 MB |
| JPEG 1600x1066 -> Auto (AVIF/WebP) | avif | 1 | 273.2 KB | 194.6 KB | 28.8% | 1005.7 | +0.71 MB |
| JPEG 1600x1066 -> WebP q80 | webp | 1 | 273.2 KB | 99.8 KB | 63.5% | 118.4 | +0.59 MB |
| JPEG 1600x1066 -> JPEG q80 (mozjpeg) | jpeg | 1 | 273.2 KB | 140.2 KB | 48.7% | 93.3 | -13.35 MB |
| JPEG 1600x1066 -> 1:1 Focal Crop WebP | webp | 1 | 273.2 KB | 101.3 KB | 62.9% | 94.6 | +0.23 MB |
| JPEG 1600x1066 -> WebP q80 (x4 parallel) | webp | 4 | 273.2 KB | 99.8 KB | 63.5% | 127.4 | +4.94 MB |

> **Note on RSS Delta**: Negative or fluctuating RSS deltas (such as `-13.35 MB` during the JPEG step) reflect V8 garbage collection and libvips buffer reuse between sequential runs rather than negative memory usage.

## 3. Quality vs Size vs CPU Trade-Offs

### AVIF vs WebP vs JPEG
- **WebP (`outputFormat: 'webp'`, `quality: 80`)**: Fastest modern format (`73.9 ms` on `1200x800` PNG; `118.4 ms` on `1600x1066` JPEG) with strong compression (`63.5%–97.9%` savings on the synthetic fixtures). Best default for high-throughput upload endpoints and latency-sensitive APIs.
- **AVIF (`outputFormat: 'avif'` or Auto)**: Delivers high perceptual quality at low bitrates for photographic content, but costs **~3.4x–8.5x more CPU time** than WebP (`252.0 ms` at `effort: 4`, `548.9–1005.7 ms` at default `effort: 6`). Lowering `effort` from `6` to `4` cut PNG->AVIF latency by more than half (`548.9 ms` -> `252.0 ms`).
- **JPEG (`outputFormat: 'jpeg'`, mozjpeg)**: Fast (`93.3 ms`) with universal legacy compatibility, though ~40% larger than WebP at `quality: 80` (`140.2 KB` vs `99.8 KB`).

### Focal Cropping & Parallelism
- **Focal-point cropping (`aspectRatio: '1:1'`, `focalPoint`)**: Adds negligible overhead compared to plain WebP (`94.6 ms` vs `118.4 ms`, because the cropped output has fewer pixels to encode).
- **Parallel batching (`x4 parallel`)**: Four concurrent `1600x1066` WebP encodes completed in `127.4 ms` total (~`31.9 ms`/image effective throughput) with `+4.94 MB` RSS delta, leveraging libvips multi-threading. In production, pair this with `createImageUploader`'s built-in Sharp semaphore (`maxConcurrency`) to bound peak memory under burst traffic.

## 4. Recommendations by Workload

| Workload | Suggested Config | Rationale |
| --- | --- | --- |
| High-traffic user uploads (avatars, social feeds) | `outputFormat: 'webp'`, `quality: 80` | Low latency (~75–120 ms), low CPU, strong compression. |
| CDN-cached hero/product imagery | Auto (`outputFormat` omitted) or `outputFormat: 'avif'`, `effort: 4` | Best long-term bandwidth savings when encode cost is amortized across many reads. |
| Legacy email / OpenGraph consumers | `outputFormat: 'jpeg'`, `quality: 80` | Maximum client compatibility with mozjpeg compression and EXIF stripping. |
